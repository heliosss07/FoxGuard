Linux Essentials

Move around the file system, understand permissions, and read logs from the command line.

Beginner 3 lessons ~35 min

Lesson 1 of 3

Finding your way around

Almost every security tool assumes you are comfortable in a terminal. Before touching any tool, you need to be able to move around the file system without a mouse.

Where are you?

pwd prints your current location. ls lists what is in it. cd changes it. 

$ pwd
                /home/student   
                $ ls
                Desktop  Documents  Downloads  tools
                $ cd tools
                $ pwd
                /home/student/tools

Shortcuts worth knowing

  • cd .. goes up one folder
  • cd ~ jumps straight to your home folder
  • cd - jumps back to wherever you just came from

Try it yourself

  • Open a terminal and run pwd
  • List the files in your home folder with ls
  • Move into any folder, then back out with cd ..

Lesson 2 of 3

Files and permissions

Every file on Linux has an owner, a group, and a set of permissions. Misconfigured permissions are one of the most common ways attackers get access they should not have, so reading them correctly matters.

Reading ls -l

$ ls -l notes.txt
                -rw-r--r-- 1 student student 220 Sep 12 09:14 notes.txt

The first character says the type (- for a normal file, d for a folder). The next nine characters are three groups of three: what the owner, the group, and everyone else can do. Each group is read (r), write (w), execute (x).

Permissions as numbers

chmod also accepts permissions as a three digit number. Each digit adds up read (4), write (2), and execute (1).

NumberPermissionsMeaning
7rwxread, write, and execute
6rw-read and write
5r-xread and execute
4r--read only
 
$ chmod 644 notes.txt

That sets read and write for the owner, and read only for everyone else, which is a safe default for a personal file.

Why this matters

A script or key file that is writable or readable by everyone is a common finding in real security audits. Locking down permissions is one of the cheapest fixes there is.

Lesson 3 of 3

Searching and logs

When something goes wrong on a system, the answer is usually already written down somewhere in a log file. Finding it fast is a core skill.

Finding files

$ find / -name "*.conf" 2>/dev/null
                /etc/ssh/sshd_config.conf
                /etc/nginx/nginx.conf

find searches by name, type, size, or when a file was changed. The 2>/dev/null part just hides "permission denied" noise.

Searching inside files

$ grep "Failed password" /var/log/auth.log
                Feb 14 03:12:41 sshd: Failed password for root from 203.0.113.9

grep searches the content of a file for a word or pattern. This one line is how you would start noticing repeated failed login attempts on a server.

Watching a log as it grows

$ tail -f /var/log/auth.log

tail -f shows the end of a file and keeps updating as new lines are added, useful while you are actively watching for something.

Try it yourself

  • Use find to look for a file type you know you have, like *.jpg
  • Use grep to search for a word inside a text file
